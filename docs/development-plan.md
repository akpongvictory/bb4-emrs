## Day 9A: User Management & Staff Onboarding
In scope:
- View facility staff
- Create a staff account and assign it to the facility
- Assign predefined role(s) and department/unit
- Activate and deactivate staff
- Reset a password (admin sets a new temporary password)
- Temporary-password onboarding and mandatory password change on first login
- Enforce existing RBAC and facility scoping on every endpoint

Technical consequences to design at the start of the day:
- User.mustChangePassword flag; a change-password endpoint
- While the flag is set, the session may only change the password, read /me and log out
- Temporary password generated by the system, shown once to the admin, stored only as an Argon2id hash
- Deactivation and password reset revoke the user's sessions
- Permissions: users.view, users.create, users.update, users.deactivate, users.assign_roles
- The email provider stays out. Keep the password and onboarding code separate from delivery so email invitations can be added later.

Out of scope: custom roles, SSO, MFA, bulk import, email delivery.

## Day 11A: Early Deployment Smoke Test
Run against a candidate backend host after the Day 11 checkpoint. Verify:
- Node.js runtime version match
- TypeScript production build
- Application startup
- Health endpoints
- Environment variables
- PostgreSQL connectivity
- Prisma behaviour (client generation, migrations)
- Argon2id install and runtime
- Secure configuration (HTTPS, secure cookies, CORS origin)
- Cookie behaviour across the frontend and API domains

This is not the final production deployment.
